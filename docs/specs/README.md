# Agent Workbench 开发规范

版本：v0.1 / MVP · 整理日期：2026-11-05。

用户已确认 [HTML 原型 v0.2](../design/design-board.html) 的视觉与主要交互，并授权进入 Spec。当前目录包含原型和设计文档；尚无 Cargo 工程或 Git 工作区。本轮交付开发规范，不代表原生应用已经实现。

## 阅读顺序

1. [产品与验收规范](workbench-v1.md)：已确认需求、完整使用流程、行为边界、验收标准。
2. [统一数据契约](data-contracts.md)：先定义项目、会话、消息、队列、文件、网页、终端、命令与事件，再由主 Agent 集中开发。
3. [架构与接入方案](architecture.md)：Rust / GPUI 组织方式、ACP、SQLite、WebView、PTY、开发顺序。
4. [设计 Token](../design/design-token.md)：从用户认可的原型提取颜色、尺寸、动效和组件映射。
5. [交互状态约定](../design/interaction-notes.md)：控件完整状态、焦点、滚动和原型模拟范围。

## 依据与维护

- **已确认需求**来自本轮对话与原型验收；无需在拆分任务时重新征询已经确认的普通选择。
- **工程决策**在规格中单独标明，用于补齐原型无法表达的并发、持久化和平台行为。
- **技术待验证项**是实现入口条件，不是用户尚未决定的需求；验证失败必须报告具体差异，不能悄悄改产品行为。
- 本目录已对应 [T01–T12 远程任务](../development/TASKS.md)；[开发指令](../development/IMPLEMENTATION.md)规定主 Agent 实现、子 Agent 辅助、集中开发和统一收尾。Rust 实现尚未启动。
- 视觉以已确认原型及 Token 为基准；业务行为以产品规范及数据契约为准；原型中的定时器、固定数据与浏览器存储仅是演示实现。
- 后续变更原位更新这组文件；保留需求编号用于任务和验收追踪。旧讨论中与本轮原型冲突的布局决定已被本规范替代。
