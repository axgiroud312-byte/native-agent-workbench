# Agent Workbench：Rust + GPUI 原生 Agent 工作台开发规范

版本：v0.1 / MVP。更新：2026-11-04。状态：已有 Rust + GPUI Kit 最小启动工程；完整 MVP、Agent 接入与用户验收尚未完成。启动工程的验证范围以 README 为准。

## 想实现什么

做一个能日常使用的开源原生桌面 Agent 工作台：打开本地项目，选择 Agent 和模型，输入文字、粘贴图片或引用文件，让 Agent 执行工作；过程中能读懂输出、补充要求、管理排队消息、回答问题、审批或停止任务，结束后能查看具体文件变化，重开应用仍能找到自己的会话。

第一版以 Windows 为使用和验收平台，优先 Codex。借鉴 Mac 窗口的简洁、高级、弱外框和弱顶栏观感，同时保留 Windows 的窗口按钮、拖动、快捷键和输入习惯。固定双栏：项目与会话侧栏，加一个连续的主工作区，不增加常驻第三栏。

多个会话可以同时工作，包括同一项目的多个会话。它们直接使用同一项目目录；用户负责分配任务，接受并行修改可能互相覆盖的取舍。关闭窗口收进系统托盘，后台任务继续；真正退出与关闭窗口是不同操作。

“智能 UI”的目标是让 AI 输出容易阅读和操作：保留真实内容，把文字、计划、工具、审批、提问和文件差异组织成合适的原生表现形式。它不是某个已经选定的框架名称，也不表示第一版需要执行 Agent 生成的任意界面代码。

## 为什么选择这个方案

### 1. 已确认的产品决定

以下是用户明确选择，后续工程调整不得悄悄改变：

| 决定 | 选择理由或接受的取舍 |
| --- | --- |
| Windows 优先，Mac 式简洁观感 | 在实际使用电脑上完成验收；Windows 不仿制红黄绿窗口按钮 |
| Rust + GPUI Kit 原生主界面 | 保留原生桌面体验，复用成熟控件，不使用 WebView 渲染主界面 |
| 不透明炭灰双栏、弱顶栏 | 让内容成为主体，通过留白、灰阶和对齐体现层次 |
| 多会话同时运行 | 切换页面不打断其他任务，侧栏能看到运行和待处理状态 |
| 同一项目共用目录 | 修改直接落到项目，操作少；不自动隔离或合并，接受文件冲突可能性 |
| Codex 优先，通过 ACP 接入 | 先完成真实闭环，UI 和内部数据仍独立于单一 Agent |
| 权限由 Agent 管理，默认完整访问 | 工作台展示和传递 Agent 设置，不自行建立第二套审批规则 |
| 模型、思考强度和权限在输入区调整 | 就近调整本次工作所需配置，实际可用项来自 Agent |
| 同时支持立即补充与排队 | 通过快捷键、一个主要发送入口和清楚反馈区分，不堆两个同等按钮 |
| 关闭窗口收进托盘 | 任务继续运行，托盘提供重新打开和真正退出 |
| 内置只读文件差异 | 能直接判断 Agent 改了什么，不扩展成代码编辑器 |
| 只管理工作台创建的会话 | 持久化和恢复自身记录，不导入已有 Codex 历史 |
| 成熟的完整输入框 | 文字、图片粘贴、附件、`/` 指令、`@` 文件引用和能力选择均属于首版 |
| 参考整个对话体验 | 参考对象不仅是输入框，还包括流式输出、工具过程、计划、问题、审批与结果整理 |
| 使用真实图标 | 使用一致的图标资源，不能用 Emoji、字母或字符拼出图标 |

### 3. 窗口、布局与视觉基线

采用 Sidebar + Main Workspace 连续表面，不使用一张张浮在背景上的大型容器。窗口推荐 1240 × 800，最小 980 × 640；这些是默认缩放下的逻辑尺寸基线，不能直接作为所有缩放环境下的固定物理像素。

| 区域 | 基线与职责 |
| --- | --- |
| Sidebar | 默认 264，允许在 240–320 调整；记住宽度，恢复时受当前窗口约束 |
| Sidebar 顶部 | 项目选择器、新建会话；与窗口拖动区域形成连续表面 |
| Sidebar 中部 | 按项目分组的会话树，独立滚动，长列表虚拟化 |
| Sidebar 底部 | 固定设置入口，不随列表滚动 |
| Workspace 顶部 | 约 44 高的轻量上下文：会话名、Agent、状态与必要操作 |
| Workspace 中部 | 独立滚动的消息与事件流，内容最大宽度建议 880 |
| Workspace 底部 | 固定输入区，随内容增长到合理上限后内部滚动 |
| 分界 | 低对比度 1px 视觉细线；实现时考虑显示缩放 |

Windows 窗口按钮放在符合 Windows 习惯的位置，保留最大化、最小化、拖动与缩放行为；顶部背景融合进工作区，不人为再加一整条高对比工具栏。侧栏顶部与会话上下文保持同层级对齐。

项目选择器决定新会话的默认项目，不隐藏其他项目的运行情况；侧栏仍可展开多个项目，避免“当前项目”与“全部会话树”含义冲突。

初始颜色只在集中主题定义处出现；业务组件读取语义 Token。

| Token | 初始值 | 用途 |
| --- | --- | --- |
| `bg.window` | `#191B1D` | 窗口底色 |
| `bg.sidebar` | `#1D1F21` | 左侧导航 |
| `bg.workspace` | `#242629` | 主工作区 |
| `bg.surface` | `#2B2D30` | 输入和工具表面 |
| `bg.hover` | `#303236` | 悬停 |
| `bg.selected` | `#35383C` | 选中 |
| `border.subtle` | `#36393D` | 分隔 |
| `text.primary` | `#E6E7E9` | 正文 |
| `text.secondary` | `#A4A8AD` | 辅助信息 |
| `text.muted` | `#777C82` | 非关键弱提示 |

间距以 4 为主要节奏，常用 8/12/16/24；侧栏主内边距 16、项目子级缩进 12、会话行高 36、项目选择器行高 40、图标 14–16。主文字 13–14，辅助 11–12，行高约 1.4–1.5。小控件圆角 6，输入 10，局部面板 8–10；同级表面一致，内外圆角与间距协调。

上述是校准起点，落地用 GPUI 相对尺度、语义尺寸与集中 Token。Windows 使用系统 UI 字体和中文回退字体；窗口外圆角服从系统，内部不再套一层圆角大框。自定义间距保存在应用设计系统中，不假定写入 GPUI Theme 后一定会按自定义值返回。焦点与状态必须可辨；不能用弱提示色承载关键错误或唯一操作入口。

使用 GPUI Kit assets/Icon 提供的统一图标族，优先其 Lucide 图标资源，实施时核对实际可用名称。需要品牌图标时采用正式资源并保留适用许可证；不要从截图裁图或用字符替代。图标按钮提供可访问名称，含义不明显时提供简短提示。

### 4. 完整输入框与原生交互

输入区不是单独一个 Textarea，而是保持稳定身份的组合：

| 位置 | 责任 |
| --- | --- |
| 输入区上方 | 当前会话排队消息，显示等待状态，支持编辑与取消；较长队列折叠 |
| 输入框内上部 | 图片缩略图与文件引用，支持预览、移除和失败重试 |
| 中部 | 多行文本、直接粘贴图片、中文输入法、选择与换行 |
| 光标或触发控件附近 | `/` 和 `@` 候选窗、可搜索菜单，超出边缘时调整位置 |
| 底部左侧 | Agent、模型、思考强度、访问权限等紧凑控件；窄窗口收起次要标签而非挤出边界 |
| 底部右侧 | 一个主要发送入口及另一发送方式菜单，运行时独立保留停止入口 |

Agent 选择属于创建会话上下文；已有会话绑定的 Agent 不直接换成另一种 Agent 并伪装成同一上下文。首版工程默认：切换 Agent 创建新会话，保留原会话。模型、思考强度、权限则在当前 Agent 支持时调整当前会话。

模型/配置选择必须区分请求值、等待确认值和实际生效值。切换模型后重新读取适用能力；不沿用失效的思考档位。运行中 Agent 不允许修改时显示原因与真实生效时机，不在 UI 中假装已经切换。完整访问是首次会话的默认请求，之后尊重用户显式选择和 Agent 的实际返回；不能覆盖组织策略或对不支持该模式的 Agent 显示假值。

`/` 选择器展示当前 Agent 报告的指令；应用自身指令若存在则明确归属。`@` 搜索当前项目文件，选择后保留文件身份而非仅一段模糊文本。列表支持筛选、上下选择、确认、Escape 关闭与焦点恢复。无匹配内容不吞掉用户输入；输入法组合输入、路径中的斜线等不能误触发发送或命令。

附件的大小、格式、数量和图像能力在实现时依据实际 Agent 限制决定并明确显示。消息记录同时保留文字和附件/引用结构，重试、队列编辑和会话切换不丢内容；不支持图片时在发送前明确说明。

两种提交意图是已确认需求；以下具体按键为可调整的工程默认，并非用户要求与某个参考项目完全一致：

| 操作 | 空闲时 | 运行中 |
| --- | --- | --- |
| `Enter` | 发送 | 立即补充 |
| `Ctrl + Enter` | 发送 | 排队发送 |
| `Shift + Enter` | 换行 | 换行 |
| `Tab` | 移动控件焦点 | 移动控件焦点 |
| `Escape` | 关闭最上层可关闭弹层 | 关闭弹层，不默认为终止任务 |

输入法确认候选和选择器确认优先于发送快捷键。菜单项显示对应快捷键，鼠标和键盘操作走同一命令；不得依赖隐藏快捷键才能使用基本功能。

队列由工作台按会话持有，不要求所有 Agent 原生提供队列。同一会话按用户顺序发送，只有前一轮明确结束才派发下一条；其他会话不受此队列阻塞。队列保存结构化内容与配置意图快照，发送前检查仍适用的实际能力。

途中补充经能力协商后调用相应扩展。Codex 适配器的 `_session/steering` 是扩展，不能当作所有 ACP Agent 必须实现的标准方法。发送遇到“当前轮刚结束”时必须按回执决定是否转入正常发送，禁止重复提交。显示“等待 Agent 接收”与“已接收”的差异，不保证发出后正在执行的系统命令能瞬间改向。

工程默认：不支持途中补充时，入口明确显示不可用并提供排队；执行失败、主动停止、断连或重启后暂停未发送队列，保留内容供用户继续，不悄悄自动再执行。模糊的网络结果需要先核对运行记录，不靠盲重试制造重复工作。

### 5. 流式输出与“智能 UI”呈现

目标是让真实信息具有阅读顺序和可操作性，不在每条回复后再调用模型生成一次美化摘要。优先利用 Agent 已提供的结构化事件；普通 Markdown 仍按原文呈现，不凭猜测把任意文本识别成可执行控件。

| 内容 | 原生呈现与交互 |
| --- | --- |
| 用户消息 | 正文与附件/引用，能识别属于哪次提交，不把未确认输入伪装成已执行 |
| Agent 正文 | 连续文档式 Markdown；标题、段落、列表、引用、表格、代码块各自清晰，支持选择与复制 |
| 流式文字 | 增量更新当前消息，避免整段闪烁与重复追加；未闭合 Markdown 能平稳过渡到完整内容 |
| 计划 | 根据真实计划事件显示步骤、当前步骤与完成状态；普通文字计划仍是文字 |
| 工具调用 | 克制的可折叠行或低对比表面：名称、摘要、运行/完成/失败，展开查看参数和结果 |
| 命令执行 | 命令与输出摘要，详细输出可展开；长输出按需加载，不构建完整终端模拟器 |
| 文件修改 | 文件列表、增删摘要、可展开的只读代码差异；来源明确指向本会话实际报告 |
| 权限请求 | 显示操作、对象、范围和 Agent 给出的选项；提交后等待确认，过期请求不能再次执行 |
| Agent 提问 | 支持协议实际提供的选择题、文本输入或表单；必填和提交状态清楚，不自己编造选项 |
| 错误与重试 | 在对应消息、工具或会话附近说明失败和恢复动作；保留输入与已有输出 |
| 未知事件 | 保留可诊断的信息，显示简短且诚实的降级内容，不使整个会话崩溃 |

“工具摘要”优先来自 Agent；缺少摘要时从明确字段生成确定性简述，不把推测写成事实。状态色克制使用，不能只靠颜色区分。已经折叠的工具组、展开的差异、选中文字和滚动位置不应因新 token 到来而重置。

用户停留底部时跟随新输出；用户向上阅读后停止强制滚动，提供“回到最新”入口。其他会话的输出不抢当前焦点。长历史和大量工具输出采用虚拟化或分段加载，批量合并渲染更新；持久化消息完成、错误、权限等语义边界，文本增量可合批写入。

Markdown 内容是内容，不可执行脚本或任意界面代码。原生展示组件保持白名单式类型分发与明确数据契约；Agent 输出一个表单并不意味着它拥有对本地 UI 或系统 API 的任意调用权限。这是实现边界，不是工作台另设 Agent 执行审批规则。

### 6. Agent 接入、状态与数据所有权

技术基线：Rust + GPUI Kit + ACP Rust SDK + Tokio + SQLite。初始工程锁定 Rust 1.98.1、`gpui-kit = 0.9.0`，提交应用 `Cargo.lock`，使用 Kit 默认 component/assets 功能。ACP、Tokio、SQLite 在对应业务实现时接入。使用核验过的公共入口，不把文档中的概念名称当成真实 API。

接入顺序：Registry 元数据与平台兼容性 → 发现本机安装 → 必要时经用户确认安装/配置 → 启动本地进程 → ACP 初始化与能力协商 → Agent 认证 → 创建或恢复工作台会话 → 标准化事件 → 更新状态与界面。

Registry 不等于安装器或认证成功；有缓存时可离线展示已知信息，本地已配置 Agent 不应因 Registry 短时不可用而完全无法使用。每个分发版本、平台和安装状态明确显示。下载和安装不能假设所有 Agent 都采用 npm。认证复用 Agent 官方机制，工作台不把凭据写入 SQLite 或日志。

Codex 首选 `agentclientprotocol/codex-acp`，其后是 Codex App Server；适配器与 Codex 版本需配套验证。Windows 分发、恢复与登录有上游文档依据，但本项目尚未跑通真实连接。使用稳定协议为基线，按实际能力启用扩展；不为草案 v2 提前承担全部兼容工作。

核心对象按业务意义命名，下面是概念契约而不是未经编译验证的 SDK 类型：

| 对象 | 所有权和必要内容 |
| --- | --- |
| Project | 本地目录与展示名称；移除索引不等于删除磁盘目录 |
| AgentDefinition | Agent 身份、来源、分发、平台与发现信息 |
| SessionRecord | 本地稳定 ID、项目、绑定 Agent、外部会话 ID、来源为本工作台 |
| Run | 一轮工作的 ID、起止、状态与结果；区分恢复历史和继续执行 |
| Message / Attachment | 消息身份、角色、正文、结构化内容、附件引用与提交状态 |
| ToolCall / FileChange | 工具 ID、所属运行、状态、输出与 Agent 报告的修改 |
| PermissionRequest / QuestionRequest | 请求 ID、所属会话和运行、可选项、是否仍有效 |
| QueuedInput / ComposerDraft | 每个会话的输入、附件、配置意图与排队/编辑状态 |
| AgentCapabilities / SessionConfiguration | 可用能力、选项及 Agent 确认的生效值 |
| AgentEvent | 有类型的内部事件，携带会话、运行、事件顺序及来源信息 |

UI 不读取原始 Agent JSON。内部至少覆盖文本增量、内容块、消息完成、计划、工具开始/更新/结束、文件变化、权限与提问、配置变化、取消、连接变化和错误。

状态不只依赖一条过度简化的枚举链：连接阶段（Starting、Authenticating、Ready、Disconnected、Failed、Closed）与执行阶段（Idle、Running、Cancelling、Completed、Cancelled、Failed）分别管理；待审批/待回答是带 ID 的请求集合。侧栏投影成用户看得懂的状态，避免同时有工具运行和问题等待时丢失事实。

关键约束：切换视图不停止任务；发出取消请求不代表已经取消；断连后晚到事件不能改写新的运行；失效审批不能被旧按钮复活；同一事件重放不能生成重复消息。并发会话独立派发，不用一把全局锁把所有任务串行化。

SQLite 保存项目、工作台会话索引、必要消息/事件、草稿与队列、布局和配置引用。附件存入应用数据目录并保存引用，不写入用户项目或公开仓库；删除记录时清理确属工作台所有的无引用附件。首次打开只查询本工作台登记的外部会话 ID，不扫描导入 Codex 全部历史。

删除语义的工程默认：移除项目只删除工作台索引和其会话记录，不删除磁盘项目；涉及正在运行的会话时先明确提示并停止受影响任务，再删除对应记录。删除本地记录不默认调用 Agent 的全局历史清理接口，不影响其他客户端创建的会话。

重新启动后先恢复本地可读记录，再按能力尝试连接原会话。历史可见不等于运行态恢复；无法恢复时保留记录并明确提供新会话入口。应用崩溃、睡眠或电脑关机时不承诺任务继续，未发送队列默认暂停。

### 7. 模块与实现约束

采用 Cargo Workspace。初始职责边界如下；是否立即拆成独立 crate 由实际规模决定，不为凑模块创建空壳。UI 内按项目、会话、对话、设置等功能组织，不把所有业务塞进全局 views/models 目录。

| 边界 | 职责 |
| --- | --- |
| app | 入口、依赖组装、窗口/托盘与退出协调 |
| ui | 原生视图、主题 Token、组合控件、对话内容呈现 |
| core | 业务对象、命令、会话状态、队列与服务接口；实现时避免与 Rust 内置 `core` 命名冲突 |
| agent-runtime | ACP 客户端、能力映射、Agent 进程树和事件转换 |
| registry | Registry 获取、缓存、平台与安装元数据 |
| storage | SQLite、迁移、附件与持久化实现 |
| platform | Windows 窗口、剪贴板、托盘和系统差异的窄接口 |

依赖由 app 组装：UI 调用 core 命令；core 面向 runtime/storage 接口，具体适配器实现接口并反馈事件。不能让 core 与 agent-runtime 相互循环依赖，UI 也不直接持有 Codex 私有实现。

工程默认每个活跃会话有独立运行上下文，进程/连接可按实际 SDK 行为安排；实现时验证多会话并发、故障影响范围和资源占用，再决定是否复用进程。GPUI 状态只在合法上下文更新，Tokio 与数据库工作不阻塞渲染线程。订阅、任务句柄与进程树有明确所有者，关闭单一会话不会杀死其他会话。

优先组件：TitleBar、Resizable、List/Tree/VirtualList、Textarea、Select/Combobox、Menu/Popover、Dialog、Tabs、Markdown TextView、只读 Diff、Icon 与合适的消息滚动组件。实际名称和签名必须查代码。产品组件包括 SessionRow、ProjectTree、Composer、ChatMessage、ToolCallView、PlanView、PermissionPrompt、QuestionForm、FileChangeView。

关闭窗口隐藏 UI，但应用状态和后台运行所有者继续存在。托盘打开复用原窗口/工作区；真正退出停止接收新任务，暂停队列，取消或终止本应用拥有的进程并完成必要保存。退出有运行任务时使用一次明确提示，不能影响其他终端启动的独立 Agent。托盘创建失败时不能把唯一窗口隐藏到无法恢复，保留可操作窗口并说明问题。

### 9. 原方案的澄清与待核实项

- 原文“macOS 红黄绿”已被用户明确改为 Windows 操作习惯，保留的是简洁观感。
- “多 Agent”当前指多个独立会话并行，Codex 优先；不等于自动协作和 Sub-Agent 编排。
- “能力检测”包括模型、思考强度、权限、命令、图片、途中补充、提问与恢复，不能只检查模型列表。
- 原来的单一状态链作为示意保留其意图，实施改为连接、执行、待处理请求分开管理，避免并发状态冲突。
- 原文组件名称是选型方向；具体 GPUI Kit 和 ACP API 必须核实，不把概念表当作可编译代码。
- 当前只实现启动工程：原生双栏窗口、集中主题、图标与临时目录选择；关闭窗口暂时退出程序，项目路径暂不持久化。托盘、可调侧栏、会话和 Agent 属于后续 MVP 工作，这些是阶段性缺口，不改变产品目标。未来发现冲突按 AGENTS.md 处理。
- 按键映射、进程复用方式、附件限额、依赖版本、Windows 安装包格式是工程待核实项；不会阻塞规格交付。若影响已确定体验，应重新讨论。
- 首版以结构化原生内容提升易读性；任意生成式 UI 运行时、HTML 原型或新 UI 框架尚未获选，不擅自引入。若需要独立交互原型，由用户另行调用设计流程。
- 仓库名 `native-agent-workbench` 和暂定产品名 Agent Workbench 已确认。仓库采用 MIT、main 分支、Issues/PR 模板、文档 CI 与 Windows Rust 构建检查。按用户要求，Spec 保留三个部分。
